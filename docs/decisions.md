# Decisions

One line per decision: date, what was decided, why. The lead adds agent assumptions here in Step C of each phase.

- 2026-10-19: MERN with Next.js for both the store and the admin; one Express API serves both. Keeps pricing and order rules in one place.
- 2026-10-19: Admin is a separate Next.js app with its own URL and login.
- 2026-10-19: Builder follows digibouquet's flow: pick a format, pick a set number of items, see them arranged, personalise, share a link.
- 2026-10-19: Items sit in slots chosen by a layout function, not free drag, so every design can be made by hand and rendered the same everywhere.
- 2026-10-19: Prices are set per country in local currency; no currency conversion.
- 2026-10-19: Both Next.js apps proxy `/api/*` to the Express API, so browser calls are same-origin and the admin cookie stays first-party.
- 2026-10-19: TypeScript is pinned to 6.0.3 and ESLint to 9.39.5: typescript-eslint does not support TypeScript 7 yet, and eslint-plugin-import does not support ESLint 10, so import order uses eslint-plugin-import-x.
- 2026-10-19: `packages/contracts` and `packages/renderer` export TypeScript source directly. Next uses `transpilePackages`, the API bundles them with tsup `noExternal`. No build-order coupling between lint, typecheck and test.
- 2026-10-19: Dates in contracts are ISO strings (the wire format); models convert to and from Date.
- 2026-10-19: `layoutType` is a plain string in contracts, validated against the renderer registry by the API, so a new layout type needs no contract change.
- 2026-10-19: A design stores one line per item (`itemId`, `qty`, unique `slot`); slot order, not array order, sets the arrangement.
- 2026-10-19: Shipping is free when goods before discount reach `freeOverMinor`, so the payment mode never changes shipping. No personalisation fee yet; `computeQuote` takes one.
- 2026-10-19: Naming a non-personalizable item reports `TEXT_TOO_LONG` (its limit is 0). An out-of-stock packaging reports `OUT_OF_STOCK`; a missing or inactive one reports only `PACKAGING_UNAVAILABLE`.
- 2026-10-19: `computeQuote` rejects non-integer shipping amounts, and `money()` normalises `-0` to `0`.
- 2026-10-19: `TransitionError` (contracts) is mapped by the API error middleware to INVALID_TRANSITION (409) or MISSING_TRANSITION_FIELD (422). An oversized body returns VALIDATION_ERROR with status 413.
- 2026-10-19: The API requires `MONGODB_URI` (no default) and refuses to start without it. `/health` and `/ready` live at the app root, not under `/v1`. `server.ts` loads `apps/api/.env` itself; Turbo's strict env mode hides shell variables from `pnpm dev`.
- 2026-10-19: Env files: `.env` for the API, `.env.local` for the Next apps. Server Components call `${API_URL}/v1` directly; browsers use the `/api` rewrite. Phase 1 must forward the session cookie from admin Server Components explicitly.
- 2026-10-19: `GiftScene` takes `{ design, packaging, items }` because a design holds only item ids. Placement anchors are the item's anchor point in a 0 to 1000 scene; real layer images are not tinted by wrapper or ribbon colour.
- 2026-10-19: Local Mongo is `mongo:8.3.13` as a single-node replica set `rs0`, no auth. Port 27017 must not be exposed publicly.
- 2026-10-19: Follow-ups from the phase 0 audit, not built yet: `/ready` should ping Mongo, not only read the Mongoose state (before phase 3); admin pages need a server-side staff session check as the first thing phase 1 delivers (rule 10); the web and admin typed API clients and env parsing are near duplicates and should be unified; API validation must reject a `layoutType` the renderer does not know, and the builder should catch `getLayout` errors; `validateDesign` does not yet reject names for items not in the design; order snapshots carry no currency of their own (it comes from `quote.currency`).
- 2026-10-19: Phase 1 route layout: public reads sit at the module root (`GET /countries`, `GET /catalog?country=`), staff routes sit under `/admin` inside the module (`/catalog/admin/items`, `/countries/admin`), auth is `/auth/*`, staff management is `/staff` (owner only). Phase 6's route-walk test relies on this.
- 2026-10-19: Seed data uses fixed ObjectIds so `pnpm seed` is idempotent without changing the item contract. `pnpm seed` needs `apps/api/.env` plus `SEED_OWNER_EMAIL` and `SEED_OWNER_PASSWORD` in the environment.
- 2026-10-19: An item's or packaging's image is an inline copy of the asset record. Saving the item after an upload or anchor change refreshes it. Asset metadata lives in the `assets` collection; image bytes live only in object storage (rule 9). Asset `url` is stored at upload time, so changing `PUBLIC_ASSET_BASE_URL` does not rewrite old URLs.
- 2026-10-19: Staff sessions: random 32-byte token in the `gp_admin` cookie, stored only as an HMAC-SHA256 hash keyed by `SESSION_SECRET`, TTL 7 days. Login is limited to 5 per minute per IP and email and answers wrong email, wrong password and inactive account identically. Owners cannot deactivate or demote themselves (409). `TRUST_PROXY_HOPS` must match the number of proxies in front of the API or rate limits share one bucket.
- 2026-10-19: Wrong upload type answers 415 and oversize 413, both with code VALIDATION_ERROR (the contract has no dedicated codes). Uploads are capped at 8 MB, decoded at most 50 megapixels, converted to WebP, longest side 1600 px.
- 2026-10-19: Next 16 renamed `middleware` to `proxy`; admin uses `src/proxy.ts` as a cheap cookie gate. Real checks happen in `lib/session.ts` (`getSession`, `requireOwner`). A layout does not re-run on client navigation, so every owner-only page calls `requireOwner()` itself.
- 2026-10-19: Money inputs in admin are typed in major units and converted by `majorToMinor` (decimal string maths, 2 minor digits for every currency). Currencies with other minor-unit sizes (none at launch) would need a per-currency exponent in the contracts.
- 2026-10-19: Phase 1 follow-ups: there is no way yet to remove a price row (set `inStock: false` to stop selling); `PUT /countries/:code` replaces nested `shipping` and `addressFormat` whole; changing a country's currency is allowed in the API but the admin UI locks it once created.
- 2026-10-19: Phase 1 audit fixes: the API rejects an unknown packaging `layoutType` (422, with the allowed list) by checking the renderer registry; CORS defaults to `WEB_ORIGIN` and `ADMIN_ORIGIN`; `SESSION_SECRET` is required when either origin is https; argon2 parameters are pinned; admin money input rejects more than two decimals instead of rounding; `pnpm seed` refuses `NODE_ENV=production` without `SEED_ALLOW_PRODUCTION=1`.
- 2026-10-19: Phase 1 audit items accepted for now: item categories are case-sensitive free text (the seed uses "Care", staff may type "care"); an item's image URL is not tied to an uploaded asset record; Mongo document shapes `CountryPriceDoc` and `AssetDoc` are local to their models (they hold storage fields the contracts do not); the login rate limiter is in-memory per process (move it to Mongo or Redis before running more than one API instance); orphaned uploads are never garbage-collected; a few test files exceed 250 lines.
- 2026-10-19: Phase 2 API: `POST /quotes` and `POST /designs` validate with `validateDesign` against the database catalog and answer 422 `DESIGN_INVALID` with `details.problems`; a coming-soon country answers 422 `VALIDATION_ERROR`; quotes are priced for each payment mode the country allows, in the country's order, from catalog prices only. Share ids are `nanoid(10)`. `GET /designs/:shareId` never fails for items that are no longer sold: it lists them in `unavailableItemIds` and sets `packagingAvailable`. Country codes in request bodies must be upper case (URLs and query strings accept either).
- 2026-10-19: Builder state is one zustand vanilla store per country, saved in `sessionStorage` under `gp-builder:<COUNTRY>` and validated on read. `useStepGuard` sends visitors to the first step whose prerequisites are missing and does nothing while the URL has `?from=<shareId>`; the review step loads that design with `loadDesign` and then removes the param. Switching format keeps lines in order until max items or capacity would be exceeded and reports what it dropped. The quote is fetched 300 ms after the design settles and only when `validateDesign` finds no problems; prices come only from that quote.
- 2026-10-19: Renderer: `GiftScene` stays server-renderable; `motion` renders the client-only `AnimatedGiftScene`. Motion ignores `transform-origin` on SVG, so items use `originX: 0`, `originY: 0` and `transformBox: "view-box"`. Animations: spring about 340 ms, fade 200 ms, all skipped under reduced motion. Images load lazily and show the placeholder until loaded, so nothing shifts.
- 2026-10-19: Share page: a full-screen overlay (`fixed inset-0`) hides the site chrome, is `noindex`, and hides "Order this gift" when the packaging is gone. `FromLoader` uses `useEffectEvent` (React 19.2+) so store callbacks do not re-trigger the fetch. Prices use the fixed locale "en" so server and browser render the same text; a per-country locale would need a field on the catalog.
- 2026-10-19: Phase 2 follow-ups: category matching on the items step is case-sensitive; a failed quote is retried only when the design changes (no manual retry button); a packaging that is out of stock but priced counts as available on the share page.
- 2026-10-19: Phase 2 audit fixes: the builder store exposes a `getServerSnapshot` (the empty pre-hydration state) so a refresh on the review step no longer fails to hydrate; the progress bar wraps instead of overflowing at 320 to 390px; the items step Continue blocks on every design problem except `TEXT_TOO_LONG`; the personalise clamp never leaves half an emoji; the API checks wrapper and ribbon colours against the packaging palette (422 with the allowed list) and answers 500 `INTERNAL` (no details) when a stored design no longer parses.
- 2026-10-19: ACCEPTED DEVIATION: an over-limit card message (over 200) or recipient name (over 40) is rejected by the zod schema (400 `VALIDATION_ERROR`), so the API never returns `TEXT_TOO_LONG` for them; the code is returned for item names (own limit, or a name on an item that is not personalizable). The builder cannot send over-limit text because it truncates at the limit.
- 2026-10-19: Deploy note: browsers reach the API through the web app's `/api` rewrite, so the API sees the web server as the client. Set `TRUST_PROXY_HOPS=1` in production (and 2 if a load balancer sits in front of the web app) or all customers share one rate-limit bucket (quotes 60 per minute, saves 20 per minute per IP).
- 2026-10-19: Phase 2 follow-ups: the coming-soon redirect goes to `/countries` (built in phase 5); items that have no price in a country are absent from the catalog, so "Not available in <country>" cannot show on the items step (only out of stock can); dev-only fake builders live under `steps/items/_dev` and `steps/arrange/dev` and are used by tests only; a few test files exceed 250 lines.
- 2026-10-19: Phase 3 order model: one `OrderModel` and one `transitionOrder` function (the only code that writes `order.status`; it checks the state machine, appends history with the actor, and writes the shipment in one conditional update so two staff cannot both move an order). Snapshots carry the item image and the packaging layers and limits, so `snapshotsToSceneDocs` redraws an order exactly as ordered after the catalog changes. `POST /orders` runs in one Mongo transaction (validate, re-price from the database, snapshot, reserve stock, insert, enqueue); a failure anywhere leaves no order, no stock change and no outbox entry, including a failing outbox write (that is a database fault and rolls back; a failing *transport* never touches the order).
- 2026-10-19: Stock: price rows may carry `stockQty`. `reserveStock` decrements in one conditional update (two orders for the last unit: one wins, one gets 409) and turns `inStock` off at zero; `releaseStock` puts units back and re-opens a row that sold out at zero. Rows without `stockQty` only use `inStock`. The admin price grid does not edit `stockQty` yet (it is preserved when prices are saved).
- 2026-10-19: Idempotency: `Idempotency-Key` is required on `POST /orders`; same key and body replays the first 2xx response for 24 h; same key and a different body, or a parallel request, answers 409 (with no `outOfStock` details); failed attempts free the key. The key is scoped by route, not by client, so a replay needs the key and the whole body. A marker older than 60 s is taken over; if a process died between commit and storing the response, a retry after 60 s could create a second order (narrow window, accepted).
- 2026-10-19: Customers prove ownership with the order number plus the phone or email (no accounts). Unknown number and wrong contact answer identically. A phone matches when the digits are equal, or when the typed national number (trunk zero dropped, at least 7 digits) is the whole stored number after a country code of at most 4 digits. Tracking and proof upload are limited to 10 per minute per IP, order placing to 20 per minute per IP.
- 2026-10-19: Country `dialCode` (optional, `+92`) is country data; checkout stores the phone with it. Countries without one send the phone as typed.
- 2026-10-19: Notifications: outbox collection `notificationOutbox`, written in the caller's transaction, sent by a worker (`NOTIFICATIONS_WORKER=on`, run it in exactly one API instance), retried 30 s, 2 min, 10 min, 1 h, 6 h then marked failed, expiring after 30 days. Delivery is at least once. The console transport masks email and phone. The order_created payload carries no customer name or email (the template reads the order). The tracking link in messages is `<WEB_ORIGIN>/track?number=<number>`.
- 2026-10-19: Payments: `prepaid` uses the manual_transfer provider and `cod` the cod provider (both return the country's instructions for `quote.dueNowMinor`); `card` throws 503 `NOT_AVAILABLE`. `recordPayment` is a service function (phase 4 exposes it): one transaction, `paymentStatus` from the sum of non-refund payments (`paid` at the total, `advance_paid` at the amount due now but below the total, else `unpaid`), confirms an `awaiting_payment` order through `transitionOrder`.
- 2026-10-19: Phase 3 audit follow-ups, accepted for now: proof images are public unlisted URLs (receipts can show account numbers; add a signed or staff-only read route in phase 6); `track` returns the country's payment instructions even for paid orders; no per-order-number limit on tracking guesses; the checkout and order lookup forms do not move focus to the error after a failed submit; notification amounts assume 2 decimals; the order-number collision retry has no test; the one-off failure of the last-unit race test under heavy load was not reproduced in 20+ runs (two other failures seen were in-memory replica set port collisions, now reduced by capping test workers at 4).
