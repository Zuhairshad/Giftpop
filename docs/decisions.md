# Decisions

One line per decision: date, what was decided, why. The lead adds agent assumptions here in Step C of each phase.

- 2026-10-19: MERN with Next.js for both the store and the admin; one Express API serves both. Keeps pricing and order rules in one place.
- 2026-10-19: Admin is a separate Next.js app with its own URL and login.
- 2026-10-19: Builder follows digibouquet's flow: pick a format, pick a set number of items, see them arranged, personalise, share a link.
- 2026-10-19: Items sit in slots chosen by a layout function, not free drag, so every design can be made by hand and rendered the same everywhere.
- 2026-10-19: Prices are set per country in local currency; no currency conversion.
- 2026-10-19: Both Next.js apps proxy `/api/*` to the Express API, so browser calls are same-origin and the admin cookie stays first-party.
- 2026-10-19: TypeScript is pinned to 6.0.3 and ESLint to 9.39.5: typescript-eslint does not support TypeScript 7 yet, and eslint-plugin-import does not support ESLint 10, so import order uses eslint-plugin-import-x.
- 2026-10-19: `packages/contracts` and `packages/renderer` export TypeScript source directly. Next uses `transpilePackages`, the API bundles them with tsup `noExternal`. No build-order coupling between lint, typecheck and test.
- 2026-10-19: Dates in contracts are ISO strings (the wire format); models convert to and from Date.
- 2026-10-19: `layoutType` is a plain string in contracts, validated against the renderer registry by the API, so a new layout type needs no contract change.
- 2026-10-19: A design stores one line per item (`itemId`, `qty`, unique `slot`); slot order, not array order, sets the arrangement.
- 2026-10-19: Shipping is free when goods before discount reach `freeOverMinor`, so the payment mode never changes shipping. No personalisation fee yet; `computeQuote` takes one.
- 2026-10-19: Naming a non-personalizable item reports `TEXT_TOO_LONG` (its limit is 0). An out-of-stock packaging reports `OUT_OF_STOCK`; a missing or inactive one reports only `PACKAGING_UNAVAILABLE`.
- 2026-10-19: `computeQuote` rejects non-integer shipping amounts, and `money()` normalises `-0` to `0`.
- 2026-10-19: `TransitionError` (contracts) is mapped by the API error middleware to INVALID_TRANSITION (409) or MISSING_TRANSITION_FIELD (422). An oversized body returns VALIDATION_ERROR with status 413.
- 2026-10-19: The API requires `MONGODB_URI` (no default) and refuses to start without it. `/health` and `/ready` live at the app root, not under `/v1`. `server.ts` loads `apps/api/.env` itself; Turbo's strict env mode hides shell variables from `pnpm dev`.
- 2026-10-19: Env files: `.env` for the API, `.env.local` for the Next apps. Server Components call `${API_URL}/v1` directly; browsers use the `/api` rewrite. Phase 1 must forward the session cookie from admin Server Components explicitly.
- 2026-10-19: `GiftScene` takes `{ design, packaging, items }` because a design holds only item ids. Placement anchors are the item's anchor point in a 0 to 1000 scene; real layer images are not tinted by wrapper or ribbon colour.
- 2026-10-19: Local Mongo is `mongo:8.3.13` as a single-node replica set `rs0`, no auth. Port 27017 must not be exposed publicly.
- 2026-10-19: Follow-ups from the phase 0 audit, not built yet: `/ready` should ping Mongo, not only read the Mongoose state (before phase 3); admin pages need a server-side staff session check as the first thing phase 1 delivers (rule 10); the web and admin typed API clients and env parsing are near duplicates and should be unified; API validation must reject a `layoutType` the renderer does not know, and the builder should catch `getLayout` errors; `validateDesign` does not yet reject names for items not in the design; order snapshots carry no currency of their own (it comes from `quote.currency`).
- 2026-10-19: Phase 1 route layout: public reads sit at the module root (`GET /countries`, `GET /catalog?country=`), staff routes sit under `/admin` inside the module (`/catalog/admin/items`, `/countries/admin`), auth is `/auth/*`, staff management is `/staff` (owner only). Phase 6's route-walk test relies on this.
- 2026-10-19: Seed data uses fixed ObjectIds so `pnpm seed` is idempotent without changing the item contract. `pnpm seed` needs `apps/api/.env` plus `SEED_OWNER_EMAIL` and `SEED_OWNER_PASSWORD` in the environment.
- 2026-10-19: An item's or packaging's image is an inline copy of the asset record. Saving the item after an upload or anchor change refreshes it. Asset metadata lives in the `assets` collection; image bytes live only in object storage (rule 9). Asset `url` is stored at upload time, so changing `PUBLIC_ASSET_BASE_URL` does not rewrite old URLs.
- 2026-10-19: Staff sessions: random 32-byte token in the `gp_admin` cookie, stored only as an HMAC-SHA256 hash keyed by `SESSION_SECRET`, TTL 7 days. Login is limited to 5 per minute per IP and email and answers wrong email, wrong password and inactive account identically. Owners cannot deactivate or demote themselves (409). `TRUST_PROXY_HOPS` must match the number of proxies in front of the API or rate limits share one bucket.
- 2026-10-19: Wrong upload type answers 415 and oversize 413, both with code VALIDATION_ERROR (the contract has no dedicated codes). Uploads are capped at 8 MB, decoded at most 50 megapixels, converted to WebP, longest side 1600 px.
- 2026-10-19: Next 16 renamed `middleware` to `proxy`; admin uses `src/proxy.ts` as a cheap cookie gate. Real checks happen in `lib/session.ts` (`getSession`, `requireOwner`). A layout does not re-run on client navigation, so every owner-only page calls `requireOwner()` itself.
- 2026-10-19: Money inputs in admin are typed in major units and converted by `majorToMinor` (decimal string maths, 2 minor digits for every currency). Currencies with other minor-unit sizes (none at launch) would need a per-currency exponent in the contracts.
- 2026-10-19: Phase 1 follow-ups: there is no way yet to remove a price row (set `inStock: false` to stop selling); `PUT /countries/:code` replaces nested `shipping` and `addressFormat` whole; changing a country's currency is allowed in the API but the admin UI locks it once created.
- 2026-10-19: Phase 1 audit fixes: the API rejects an unknown packaging `layoutType` (422, with the allowed list) by checking the renderer registry; CORS defaults to `WEB_ORIGIN` and `ADMIN_ORIGIN`; `SESSION_SECRET` is required when either origin is https; argon2 parameters are pinned; admin money input rejects more than two decimals instead of rounding; `pnpm seed` refuses `NODE_ENV=production` without `SEED_ALLOW_PRODUCTION=1`.
- 2026-10-19: Phase 1 audit items accepted for now: item categories are case-sensitive free text (the seed uses "Care", staff may type "care"); an item's image URL is not tied to an uploaded asset record; Mongo document shapes `CountryPriceDoc` and `AssetDoc` are local to their models (they hold storage fields the contracts do not); the login rate limiter is in-memory per process (move it to Mongo or Redis before running more than one API instance); orphaned uploads are never garbage-collected; a few test files exceed 250 lines.
- 2026-10-19: Phase 2 API: `POST /quotes` and `POST /designs` validate with `validateDesign` against the database catalog and answer 422 `DESIGN_INVALID` with `details.problems`; a coming-soon country answers 422 `VALIDATION_ERROR`; quotes are priced for each payment mode the country allows, in the country's order, from catalog prices only. Share ids are `nanoid(10)`. `GET /designs/:shareId` never fails for items that are no longer sold: it lists them in `unavailableItemIds` and sets `packagingAvailable`. Country codes in request bodies must be upper case (URLs and query strings accept either).
- 2026-10-19: Builder state is one zustand vanilla store per country, saved in `sessionStorage` under `gp-builder:<COUNTRY>` and validated on read. `useStepGuard` sends visitors to the first step whose prerequisites are missing and does nothing while the URL has `?from=<shareId>`; the review step loads that design with `loadDesign` and then removes the param. Switching format keeps lines in order until max items or capacity would be exceeded and reports what it dropped. The quote is fetched 300 ms after the design settles and only when `validateDesign` finds no problems; prices come only from that quote.
- 2026-10-19: Renderer: `GiftScene` stays server-renderable; `motion` renders the client-only `AnimatedGiftScene`. Motion ignores `transform-origin` on SVG, so items use `originX: 0`, `originY: 0` and `transformBox: "view-box"`. Animations: spring about 340 ms, fade 200 ms, all skipped under reduced motion. Images load lazily and show the placeholder until loaded, so nothing shifts.
- 2026-10-19: Share page: a full-screen overlay (`fixed inset-0`) hides the site chrome, is `noindex`, and hides "Order this gift" when the packaging is gone. `FromLoader` uses `useEffectEvent` (React 19.2+) so store callbacks do not re-trigger the fetch. Prices use the fixed locale "en" so server and browser render the same text; a per-country locale would need a field on the catalog.
- 2026-10-19: Phase 2 follow-ups: category matching on the items step is case-sensitive; a failed quote is retried only when the design changes (no manual retry button); a packaging that is out of stock but priced counts as available on the share page.
- 2026-10-19: Phase 2 audit fixes: the builder store exposes a `getServerSnapshot` (the empty pre-hydration state) so a refresh on the review step no longer fails to hydrate; the progress bar wraps instead of overflowing at 320 to 390px; the items step Continue blocks on every design problem except `TEXT_TOO_LONG`; the personalise clamp never leaves half an emoji; the API checks wrapper and ribbon colours against the packaging palette (422 with the allowed list) and answers 500 `INTERNAL` (no details) when a stored design no longer parses.
- 2026-10-19: ACCEPTED DEVIATION: an over-limit card message (over 200) or recipient name (over 40) is rejected by the zod schema (400 `VALIDATION_ERROR`), so the API never returns `TEXT_TOO_LONG` for them; the code is returned for item names (own limit, or a name on an item that is not personalizable). The builder cannot send over-limit text because it truncates at the limit.
- 2026-10-19: Deploy note: browsers reach the API through the web app's `/api` rewrite, so the API sees the web server as the client. Set `TRUST_PROXY_HOPS=1` in production (and 2 if a load balancer sits in front of the web app) or all customers share one rate-limit bucket (quotes 60 per minute, saves 20 per minute per IP).
- 2026-10-19: Phase 2 follow-ups: the coming-soon redirect goes to `/countries` (built in phase 5); items that have no price in a country are absent from the catalog, so "Not available in <country>" cannot show on the items step (only out of stock can); the dev-only fake builder lives under `steps/items/_dev` and is used by tests only (the unused `steps/arrange/dev` harness was removed); a few test files exceed 250 lines.
- 2026-10-19: Phase 3 order model: one `OrderModel` and one `transitionOrder` function (the only code that writes `order.status`; it checks the state machine, appends history with the actor, and writes the shipment in one conditional update so two staff cannot both move an order). Snapshots carry the item image and the packaging layers and limits, so `snapshotsToSceneDocs` redraws an order exactly as ordered after the catalog changes. `POST /orders` runs in one Mongo transaction (validate, re-price from the database, snapshot, reserve stock, insert, enqueue); a failure anywhere leaves no order, no stock change and no outbox entry, including a failing outbox write (that is a database fault and rolls back; a failing *transport* never touches the order).
- 2026-10-19: Stock: price rows may carry `stockQty`. `reserveStock` decrements in one conditional update (two orders for the last unit: one wins, one gets 409) and turns `inStock` off at zero; `releaseStock` puts units back and re-opens a row that sold out at zero. Rows without `stockQty` only use `inStock`. The admin price grid does not edit `stockQty` yet (it is preserved when prices are saved).
- 2026-10-19: Idempotency: `Idempotency-Key` is required on `POST /orders`; same key and body replays the first 2xx response for 24 h; same key and a different body, or a parallel request, answers 409 (with no `outOfStock` details); failed attempts free the key. The key is scoped by route, not by client, so a replay needs the key and the whole body. A marker older than 60 s is taken over; if a process died between commit and storing the response, a retry after 60 s could create a second order (narrow window, accepted).
- 2026-10-19: Customers prove ownership with the order number plus the phone or email (no accounts). Unknown number and wrong contact answer identically. A phone matches when the digits are equal, or when the typed national number (trunk zero dropped, at least 7 digits) is the whole stored number after a country code of at most 4 digits. Tracking and proof upload are limited to 10 per minute per IP, order placing to 20 per minute per IP.
- 2026-10-19: Country `dialCode` (optional, `+92`) is country data; checkout stores the phone with it. Countries without one send the phone as typed.
- 2026-10-19: Notifications: outbox collection `notificationOutbox`, written in the caller's transaction, sent by a worker (`NOTIFICATIONS_WORKER=on`, run it in exactly one API instance), retried 30 s, 2 min, 10 min, 1 h, 6 h then marked failed, expiring after 30 days. Delivery is at least once. The console transport masks email and phone. The order_created payload carries no customer name or email (the template reads the order). The tracking link in messages is `<WEB_ORIGIN>/track?number=<number>`.
- 2026-10-19: Payments: `prepaid` uses the manual_transfer provider and `cod` the cod provider (both return the country's instructions for `quote.dueNowMinor`); `card` throws 503 `NOT_AVAILABLE`. `recordPayment` is a service function (phase 4 exposes it): one transaction, `paymentStatus` from the sum of non-refund payments (`paid` at the total, `advance_paid` at the amount due now but below the total, else `unpaid`), confirms an `awaiting_payment` order through `transitionOrder`.
- 2026-10-19: Phase 3 audit follow-ups, accepted for now: proof images are public unlisted URLs (receipts can show account numbers; add a signed or staff-only read route in phase 6); `track` returns the country's payment instructions even for paid orders; no per-order-number limit on tracking guesses; the checkout and order lookup forms do not move focus to the error after a failed submit; notification amounts assume 2 decimals; the order-number collision retry has no test; the one-off failure of the last-unit race test under heavy load was not reproduced in 20+ runs (two other failures seen were in-memory replica set port collisions, now reduced by capping test workers at 4).
- 2026-10-19: Phase 5 routes: `GET /countries` and `GET /templates?country=` are public and cached 5 minutes in the web app (`next: { revalidate: 300 }`); staff routes are under `/admin` in each module (`/partner-requests/admin`, `/templates/admin`). `/<cc>` is the home of one country (templates, formats), `/` is the generic home, and `proxy.ts` (Next 16's name for middleware) redirects `/` to `/<cc>` when a valid `gp_country` cookie exists. Because the header reads cookies, every web route is dynamic; only the API data is cached. A country flipped to coming soon or live can take up to 5 minutes to change on `/countries`, the picker and the home data; `/<cc>`, the builder and checkout are uncached and change at once.
- 2026-10-19: Partnerships: public `POST /partner-requests` is limited to 3 per hour per IP and the limiter runs before validation, so invalid requests and honeypot hits use the quota (set `TRUST_PROXY_HOPS=1` in production or the whole site shares one 3-per-hour bucket). The honeypot field is `gp_hp_contact_ref`, read from the raw body: a non-blank value gets the same 201 and stores nothing. A brand `link` must be an http(s) address or text with no colon or spaces (handle, `www.shop.com`); the admin only makes http(s) links clickable. Staff alerts are `staff_alert` outbox messages with no contact details and no control characters; each status change adds a system note with the actor. A stored row that no longer parses answers 500.
- 2026-10-19: Templates: a template stores the saved design's JSON plus its `shareId`, a description and a country list; the public list only includes templates that are active, listed for the country, and sellable there (`validateDesign` against the live catalog, including min and max items and capacity). `POST /templates/:id/start` without a country picks the first listed country that is live and can still make the gift. The share view and the review step's `?from=` take `?country=` so availability is judged for the visitor's country. Home cards link to `/<cc>/build/review?from=<shareId>`.
- 2026-10-19: Phase 5 follow-ups, accepted for now: a stale or forged `gp_country` cookie for a country that does not exist sends `/` to a 404 until the picker is used (the proxy cannot ask the API); focus drops to the page after "Not now" on the country banner; countries cannot be deleted through the API (only flipped to coming soon); admin partner and template screens import small helpers from `features/catalog` (move them to shared code later); the country list in the picker shows "No countries are open yet" when the API is down.
- 2026-10-19: Phase 4 admin orders: all routes under `/v1/admin/orders` sit behind one `requireStaff()`. List uses an opaque cursor (createdAt, then id), newest first; search matches order number (exact), email (exact, case-insensitive) or a phone typed in any format. `POST /:id/status` validates only the shape (`TransitionFieldsSchema`), so a missing courier, tracking number or reason answers 422 `MISSING_TRANSITION_FIELD` only after the state machine accepts the move; cancelling also puts stock back in the same transaction. Payments take the order's currency (the browser never sends one), and a refund larger than what was received (net of earlier refunds) is refused with 422. Proof review and notes are staff-only; notes never reach the public track view or notifications.
- 2026-10-19: Dashboard: `needsAction` counts by status (awaiting payment counts only with a pending proof); "today" and revenue use the UTC day and one row per currency (payments recorded today, never summed across currencies); orders by country covers the last 30 days. The pipelines hint their indexes, so the API now calls `model.init()` for every model before it listens (a hint on an index that is still building would fail). Indexes must be allowed to build in production (do not disable `autoIndex` without a deploy step that runs `syncIndexes`).
- 2026-10-19: Admin UI: staff-facing errors never show API text (`describeActionError`); the status menu offers only `nextStatuses`; the payment dialog parses typed money from the decimal string and refuses more than 2 decimals; the packing sheet fits one A4 page for a 10-item bouquet (checked by rendering a PDF); colour words on it come from a small nearest-colour table and are display-only.
- 2026-10-19: Phase 4 follow-ups, accepted for now: admin money maths assumes 2 minor digits for every currency (move the exponent into contracts when a currency needs another); proof review records no actor or history entry; address labels on the order detail are fixed English; the "last unit" race tests failed once each under full-suite load and passed in every isolated and repeat run (the assertion now prints both response bodies so the next occurrence shows the cause); a few files are slightly over 250 lines.
- 2026-10-19: Phase 6 payment proofs: a proof's `url` now holds the staff-only file path, and the real storage key lives in the Mongoose-only `storageKey` (missing on proofs stored before proofs went private). R2 proofs go to `R2_PRIVATE_BUCKET`, falling back to the public bucket when it is unset (set it in production). `ReadableStorage` is a separate interface from `Storage` for now (merge later).
- 2026-10-19: Phase 6 hardening: login is also limited per IP (30 a minute) besides per IP and email; a global guard rejects any `$` or dotted key in bodies and queries; staff writes need an `Origin` equal to `ADMIN_ORIGIN` (set it exactly as the staff browser sees it). Deploy assumptions are listed in `docs/audit/deploy.md` (`pnpm deploy --prod` with `--config.inject-workspace-packages=true`, two Vercel projects with `API_URL` at build and runtime, deploy workflows manual and gated by `vars.DEPLOY_ENABLED`).
- 2026-10-19: Phase 6 security lows, accepted for now (`docs/audit/security.md`): S11 the 404 message echoes method and path; S12 body-parser accepts any `utf-*` charset (the key guard and zod run on the decoded object); S13 `cors` sends `Allow-Credentials` without `Allow-Origin` to unlisted origins; S14 rate limits are in memory, so run one API instance and keep `TRUST_PROXY_HOPS` right; S15 staff sessions last 7 days with no idle timeout or rotation; S16 passwords 10 to 200 characters, no breached-password check; S17 logout and public reads have no rate limit; S18 idempotency keys are scoped by route; S19 tracking is limited per IP only; S20 the store's `/api/*` rewrite exposes the whole API (staff routes still need a session and an admin `Origin`); S21 a client `x-request-id` up to 100 characters is echoed and logged.
- 2026-10-19: Phase 6 e2e lows, accepted for now (`docs/audit/e2e.md`): taps before hydration do nothing on the format cards and Continue; order page, track and proof share one 10-per-minute limiter per IP; templates are cached 5 minutes in the web app; a click on an admin order row while the search is still filtering can be lost; the seed loads no featured template. The isolated run (`E2E_ISOLATED=1`) seeds in the API server command, before the API listens: Playwright starts the servers before global setup, and the web readiness probe would otherwise cache an empty country list for 5 minutes on a fresh database.
- 2026-10-19: Money is shown with the ISO 4217 minor-unit digits from `minorDigits()` in `contracts/money` (2 for every launch currency), never with `Intl`'s display digits: CLDR 48 (Node 22.23, ICU 78) shows PKR with 0 decimals, which made both apps show PKR prices 100 times too high. The formatters also pin Intl's fraction digits so it never rounds for display. Typed money is parsed by `majorToMinor(text, currency)` and shown by `minorToMajor(minor, currency)` in `contracts/money` (admin catalog inputs, price grid, payment dialog, API notification amounts), so a JPY (0) or KWD (3) country needs no code change.
- 2026-10-19: Orders snapshot the palette names of the chosen colours (`packaging.wrapperColorName`, `ribbonColorName`, optional in the contract because older orders lack them). Order detail and the packing sheet show the saved name and fall back to the nearest colour word.
- 2026-10-19: Admin order search matches `searchKeys` (`email` lower-cased and trimmed, `phoneDigits`), stored on the order beside the frozen contact by a validate hook on create and indexed; the contact itself is not changed. The API boot backfills orders without keys with one update pipeline (idempotent; logs how many). A phone matches when its digits are equal, as before (a typed national number such as 0300 1234567 does not find +92 300 1234567). The backfill lowercases with Mongo `$toLower` (ASCII only) while new orders use JS `toLowerCase`; only an email with non-ASCII capitals could differ. The old `contact.email` and `contact.phone` indexes are no longer used by the search; drop them in a later deploy if nothing else needs them.
- 2026-10-19: Performance: `GiftScene motion` loads `AnimatedGiftScene` lazily through the small client module `scene/MotionScene.tsx`, with the static scene as the Suspense fallback (a lazy import inside a Server Component made Next preload motion on every route); `AnimatedGiftScene` is exported from `@giftpop/renderer/animated`, not the barrel. `LazyMotion` with `domAnimation` and `m` inside it. `contracts` and `renderer` are `sideEffects: false`. Item cards use `next/image` (`sizes="112px"`), so web and admin need `PUBLIC_ASSET_BASE_URL`. First-load JS gzip, before and after: `/` 224 to 168 kB, `/pk` 225 to 169, `/track` 230 to 180, review 237 to 187, checkout 237 to 188, items 237 to 238, arrange 236 to 231 (these two animate). zod stays on the client (31 kB) because client code parses API responses; moving to `zod/mini` would be a contracts-wide change. Scene images go through the optimiser too: `GiftScene` takes `imageUrl(url, width)` and rewrites the input's asset URLs (items 256 px, layers 750 px) before either path, so only data reaches the client scene. The web helper `lib/image-url.ts` resizes only URLs under `NEXT_PUBLIC_ASSET_BASE_URLS` (inlined by `next.config.ts` from `PUBLIC_ASSET_BASE_URL`) and leaves any other URL as it is, and item cards fall back to `unoptimized`, so an unset value or an image saved under an earlier base URL still loads. The items (238 kB) and arrange (231 kB) steps stay above the 200 kB budget because they animate; the owner must accept that or ask for a lighter animation.
- 2026-10-19: Deploy: `SEED_OWNER_ONLY=1` creates the first owner and writes no catalog, and may run in production without `SEED_ALLOW_PRODUCTION`. Web and admin refuse to fall back to `http://localhost:4000` for `API_URL` when `NODE_ENV=production` (`next build` included; CI sets `API_URL` for its build step). `/ready` sends a Mongo `ping` with a 2 second limit. A blank `SESSION_SECRET` (as in `.env.example`) counts as unset. Boot logs a warning when `NOTIFICATIONS_WORKER` is off in production. Deploy finding 2 was already enforced (production refuses local storage, and R2 refuses a localhost asset host). Still open from `docs/audit/deploy.md`: the proxy shared secret before `TRUST_PROXY_HOPS` goes above 1 (needs an owner decision: it spans all three apps), in-memory limiters (run one API instance).
- 2026-10-19: Accessibility follow-ups done: the items step renders `ItemsSkeleton` before the store hydrates and in `loading.tsx` (CLS 0 at 390 px, Fast 3G, 4x CPU); checkout has a `role="alert"` error summary per failed submit; stepper buttons are "Plus: add one more X" and "Minus: remove one X"; the template link and the admin account menu have an `aria-label` that begins with their visible text (an `sr-only` span made Chrome insert a space: "Start from this : …").
- 2026-10-19: `POST /templates/:id/start` takes `TemplateStartRequestSchema` from contracts. `SEED_OWNER_ONLY` (and the full seed) refuse when the email already belongs to a staff account or an inactive owner, and change nothing.
- 2026-10-19: Phase 7 redesign (design system in `docs/design/giftpop-DESIGN.md`). Packaging has a `kind` (box, bouquet, basket, mug, other; missing reads as box) so the builder's first question can group them; seed gained a round hat box, a gift basket and a mug bouquet on the two existing layouts. Orders do not snapshot `kind`. Fonts: Bricolage Grotesque (display), Inter (text), Caveat (handmade accent: eyebrow, step label, gift tags), Pacifico as a placeholder wordmark until the owner supplies the logo. Colour tokens, radii (4/8/12/20/full), shadows and springs live in `apps/web/src/styles/` (`tokens.css`, `motion.ts`); the older token names stay as aliases.
- 2026-10-19: Builder is one route, `/<cc>/build`, with a live overview and six questions (registry in `features/builder/questions/registry.ts`: id, title, continue label, body, can-continue hook). The current question is saved per country in sessionStorage (`gp-builder-question:<CC>`) and validated on read; old step URLs redirect to `/build` and carry `?from`. `BuilderProvider` stays in the layout so the store survives `?from=` being removed. The review question shows the card (recipient and message), both price columns and "Save and share"; the old per-item and personalisation lists are gone because the overview shows the gift. Drag reorder was removed: reorder is buttons only. The shell's `domAnimation` import is static (an async `LazyMotion` load left questions stuck).
- 2026-10-19: Pages that must fill the viewport put `data-viewport-fit` on a root element inside `<main>`; `globals.css` then makes the body exactly `100dvh` with no scroll, `main` full-bleed, and (`builder`) hides the footer. The floating country suggestion is hidden on those pages (it covered the headline; the header chip is right there) and still shows elsewhere, where it can still overlap the top of the content (follow-up: put it in flow).
- 2026-10-19: Home hero: plain `three` (no react-three-fiber, no drei): R3F kept the lazy chunk at 302 kB gzip against 202 kB. The SVG poster is the resting frame and the LCP; the canvas starts 2.5 s after `load` (then idle), renders at 30 fps once settled, pauses when hidden or off screen, and is skipped for reduced motion, no WebGL, or any error. Timings are in `hero3d/constants.ts` and are a draft: the owner's notes on the prompt-motion pieces (the site returned 403 here) are still to come. Without the start delay Lighthouse mobile gave the home 64 (blocking time 9 s from software GL in a GPU-less lab); with it 90 to 91.
- 2026-10-19: Illustrations: one component per item shape and per layout type behind `ITEM_ILLUSTRATIONS` / `PACKAGING_ILLUSTRATIONS` in `packages/renderer`, tinted from the item `color` and the chosen wrapper and ribbon. Roots keep `data-placeholder="<shape>"` (scene tests count art by it). A real uploaded image still wins.
